# ADR 0001: Canonical Annotation Model

- Status: Accepted
- Date: 2026-10-28

## Context

このプロジェクトは、音声の文字起こし、読みの人手確認、GeminiとF0によるアクセント句/H-L推定、VOICEVOXでの合成をつなぐ。

VOICEVOXのAudioQueryを唯一の保存形式にすると、合成エンジン固有の構造と、研究・アノテーション上必要な情報が混ざる。また、Geminiの推定と人間による修正を区別できなくなる。

## Decision

プロジェクト独自のエンジン非依存なアノテーションモデルを正規データとして保存する。

最低限、次の情報を分離して保持する。

- 元音声の参照情報
- 文字起こしテキスト
- 人間が確認した読みと確認状態
- モーラ列と、必要に応じた音声上の開始・終了時刻
- モーラごとのH/Lラベル（H / L / null）
- アクセント句のモーラ範囲
- ラベルの出典、信頼度、レビュー状態
- 修正メモや履歴

VOICEVOXとの連携では、正規データとVOICEVOX AudioQueryの間に変換層を置く。

## Alternatives considered

### VOICEVOX AudioQueryを正規データにする

採用しない。VOICEVOXの形式は合成には便利だが、エンジンに依存し、独自のH/Lラベルや推定の出典・レビュー状態を表すための正規形式としては不十分。

### 文章とH/L文字列だけで保存する

採用しない。モーラの時間位置、アクセント句の範囲、推定の出典や不確実性を構造的に扱いにくい。

## Consequences

- 将来的に別の音声合成エンジンを追加しやすい。
- 人間による修正と自動推定を区別できる。
- 正規データからVOICEVOXへの変換処理が必要になる。
- モーラ分割、時間アラインメント、H/Lの定義は明示的に管理する必要がある。

## Follow-up work

- 正規データのJSON Schemaを定義する。
- モーラ列と音声時刻の対応付け方法を決める。
- H/Lの定義とアクセント句境界のアノテーション規約を文書化する。
- 推定・人手修正の履歴を保存する方式を検討する。
