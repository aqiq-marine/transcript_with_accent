# Agent Instructions

このファイルは、このリポジトリを変更するAIコーディングエージェントおよび開発者向けの作業規約です。

## Project goal

日本語音声を対象に、次の作業を支援する。

1. 音声の文字起こし
2. 読みの推定と人間による確定
3. GeminiとF0を組み合わせたアクセント句・モーラ単位H/Lの候補推定
4. 人間によるレビュー・修正
5. 正規アノテーションからVOICEVOX `.vvproj` プロジェクトを生成し、VOICEVOXエディター上で編集・合成する

## Core principles

- 推定結果と人間が確定した結果を区別する。
- Geminiの出力、F0由来の推定、辞書由来の情報を、出典を保持して扱う。
- 読みの確認をアクセント推定より先に行う。
- モーラ境界と音声時間の対応が不確かなとき、H/Lを確定済みとして保存しない。
- アクセント句境界とモーラごとのH/Lは別のラベルとして扱う。
- プロジェクト独自のエンジン非依存アノテーションを正規データとする。VOICEVOX形式はエクスポート先として扱う。
- VOICEVOX連携の成果物は、VOICEVOXエディターで開ける `.vvproj` ファイルとする。
- VOICEVOX Engine APIは合成用クエリの作成・音声合成に使うAPIであり、APIへの送信だけでエディターのプロジェクトファイルが生成・同期されるとは想定しない。
- 曖昧な情報はnullやレビュー待ち状態で表し、根拠のない値を捏造しない。

## Implementation rules

- 既存の構成・依存関係を確認してから変更する。
- 変更は小さく、目的を絞る。
- 公開APIや保存スキーマを変更するときは、テストとドキュメントを同時に更新する。
- APIキーや秘密情報をソースコード、テストフィクスチャ、ログに含めない。
- 外部API呼び出しはタイムアウトと、利用者が理解できるエラーを用意する。
- 音声ファイルは大きくなりやすいため、サンプル音声を追加する際はライセンスとサイズを確認する。
- F0値は話者・発話スタイル・無声区間に依存する。単純な固定閾値を正解判定として扱わない。
- 拗音を含むモーラの分割規則を一貫させる。
- 時刻の単位は秒、モーラ区間は半開区間 [start, end) に統一する。変更する場合はADRで記録する。
- `.vvproj` の内部構造はVOICEVOXエディターのバージョンに依存し得る。手書きの部分スキーマだけで生成成功を仮定せず、最小ファイルを実際のエディターで開く統合テストを行う。
- 可能ならVOICEVOXで保存したサンプルファイルと公式エディターのスキーマ／読み込み処理を根拠にし、未確認のフィールドを推測で追加しない。

## Validation

変更後は利用可能な範囲で単体テスト、スキーマ検証、静的解析を実行する。Gemini APIやVOICEVOXが必要な統合テストは、資格情報やサービスがない環境ではスキップし、その制約を明記する。

`.vvproj` 生成の変更では、生成物が対象VOICEVOXバージョンで開けること、およびテキスト・読み・アクセント・話者情報が保持されることを可能な範囲で検証する。

## Documentation

- 実装状況とREADMEの説明を一致させる。
- 新しい主要機能を追加したら、データフロー、設定、制約を更新する。
